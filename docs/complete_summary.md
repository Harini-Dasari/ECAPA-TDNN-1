## 3. Core Model and Evaluation Work

### 3.1 `ECAPAModel.py`
This file was inspected and documented in detail.

What it does:
- defines the ECAPA-TDNN wrapper class
- creates the speaker encoder
- creates the AAM-Softmax loss
- handles training and evaluation
- computes scores, EER, and minDCF
- generates score-distribution and threshold-sweep plots
- saves and loads checkpoints

Key evaluation behavior:
- It computes full-utterance and split-utterance embeddings for each trial file.
- It scores pairs using cosine-like similarity through matrix multiplication and averaging.
- It computes EER with `tuneThresholdfromScore`.
- It computes FNR/FPR curves and minDCF with `ComputeErrorRates` and `ComputeMinDcf`.
- It caches `scores` and `labels` so downstream threshold sweeps can reuse them without recomputing embeddings.

Threshold values used in this file:
- `tuneThresholdfromScore(scores, labels, [1, 0.1])`
- `ComputeMinDcf(..., 0.05, 1, 1)`
- fine-grained sweep from `-1.0` to `1.0` with step `0.001`

### 3.2 `trainECAPAModel.py`
This file was modified and explained in detail.

What it does:
- parses command-line arguments
- builds the training loader when training
- loads a pretrained model when evaluating
- runs the main evaluation
- runs fixed-threshold evaluation
- saves CSV and plot outputs

Important changes made:
- Added `evaluate_fixed_thresholds(...)` to reuse cached scores from `ECAPAModel.eval_network()`.
- Added debug printing and flushes so terminal output is visible during long runs.
- Added CSV and plot saving for threshold evaluation.
- Added a `--final_eval_dir` option later so evaluation outputs could be copied into `exps/final_eval`.
- Added `shutil` so CSV and PNG files could be copied to the final results folder.

Threshold values used in the final version:
- `fixed_thresholds = [0.30, 0.31, 0.32, 0.33, 0.34]`
- final evaluation threshold `0.31`

Output files generated by this workflow:
- `exps/eval_gpu/threshold_030_034_results.csv`
- `exps/eval_gpu/far_frr_vs_threshold_030_034.png`
- `exps/eval_gpu/fixed_threshold_results.csv`
- copies in `exps/final_eval` when final evaluation is run

### 3.3 `threshold_sweep.py`
This file became the cleaner dedicated threshold analysis script.

What it does:
- loads a pretrained model
- reads a trial list
- extracts embeddings once and caches them
- scores all pairs
- sweeps thresholds efficiently
- writes a detailed CSV and JSON summary

Important threshold settings:
- default sweep start: `0.1`
- default sweep end: `1.0`
- default step: `0.1`
- custom analysis used: `0.30` to `0.34` with step `0.01`

This file is the best script for proper threshold experiments because it is structured, repeatable, and cache-aware.

### 3.4 `final_evaluate.py`
This file was added later as a final evaluation runner.

What it does:
- loads the pretrained model
- runs evaluation on a trial list
- computes metrics at a fixed threshold
- saves per-list CSV and PNG outputs
- writes a global summary CSV
- stores everything in `exps/final_eval`

Default threshold used:
- `0.31`

Final outputs generated from the run:
- `exps/final_eval/veri_test2_threshold_310_summary.csv`
- `exps/final_eval/veri_test2_score_distributions.png`
- `exps/final_eval/veri_test2_far_frr_curve.png`
- `exps/final_eval/final_eval_summary.csv`

The final evaluation run completed successfully in WSL.

## 9. RedDots Analysis

A separate investigation was done on the `reddots/` folder.

What was found:
- RedDots is a text-dependent speaker recognition corpus.
- It uses `.trn` and `.ndx` protocol files.
- Audio is stored as raw `.pcm` files.
- It has separate parts and enrollment strategies for text-dependent evaluation.

Important RedDots details:
- Part 01: Common Pass-phrases Text-Dependent
- Part 02: Unique Pass-phrases Text-Dependent
- Part 03: Free-choice Pass-phrases Text-Dependent
- Part 04: Text-Prompted

Key conclusion:
- The current VoxCeleb-style evaluation pipeline cannot be reused for RedDots without changes.
- Threshold `0.31` can be used only as a temporary baseline, not as a final RedDots threshold.
- RedDots requires its own protocol parsing, PCM audio handling, and threshold calibration.

A report was written to:
- `docs/reddots_analysis_report.md`

## 10. Main Threshold Conclusions

### For the original VoxCeleb-style evaluation
- Final threshold: `0.31`
- This threshold gave the best balance in the fine-grained sweep.
- It was used successfully in the final evaluation run.

### For RedDots
- Do not assume `0.31` is the correct final threshold.
- Threshold must be tuned separately for RedDots development data.
- The evaluation protocol is text-dependent, so the score distribution may shift.
